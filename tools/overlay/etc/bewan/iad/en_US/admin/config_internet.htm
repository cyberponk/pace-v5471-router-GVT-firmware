Internet

Internet connection on the WAN port (router mode). With USB tethering failover on (USB Devices page), a phone plugged into the USB port takes over while this connection is down.

Connection
Connection type:PPPoE: fiber/DSL modem in bridge mode, with an account from the provider. DHCP: the modem or another router gives the address. Fixed IP: address given by the provider.
Account:PPPoE user name given by the provider (often user@provider).
Password:PPPoE password given by the provider.
Leave empty to keep the current password.
No password
Service name:PPPoE service name; only some providers use it.
Optional. Leave empty unless your provider requires one.
IP address:Fixed public or WAN address given by the provider.
Subnet mask:Mask given by the provider.
Gateway:Provider router the Internet traffic is sent to.
DNS servers:Name servers used by the router and handed to the devices.
Separated by commas.
WAN port
VLAN tag:Some fiber providers require the Internet traffic to carry a VLAN number. Off = normal Ethernet (DHCP from another router, most modems).
VLAN ID:VLAN number required by the provider.
Only if your provider requires it (for example 600 for Vivo/GVT).
MAC address clone:Use another MAC address on the WAN port, for providers or modems that only accept the device registered before.
MAC address:MAC address to use on the WAN port.
For example the address of your previous router.
Internet check
Monitoring addresses:Pinged every 5 seconds through the WAN and through the USB phone to check that the Internet works: the WAN counts as down when none of them answers. Up to 4 IP addresses separated by commas (default 1.1.1.1, 8.8.8.8).
Isolate from the WAN-side network:On: computers on this router's network can't reach the devices of the network the WAN port is connected to (for example the other router's network); the Internet keeps working. Off: they can, like any other address.
DNS
DNS over TLS:The router sends the name lookups of all devices encrypted (TLS, port 853) to the chosen provider, so the Internet provider and the network on the WAN side can neither read nor change them. Off: the DNS servers of the connection are used, unencrypted.
DNS rebinding protection:Answers that point an Internet name to a private address (192.168.x.x, 10.x.x.x...) are dropped, so a web page can't use your browser to reach the router or other local devices. Local names (.local, .lan, .home, .home.arpa, .internal) are allowed.
